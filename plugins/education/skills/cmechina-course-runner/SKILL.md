# CMEChina 课程助手

## 用法

Claude Code：`/education:cmechina-course-runner 完成 https://www.cmechina.net/cme/study2.jsp?course_id=123&courseware_id=01 的全部小节`。Codex：`$cmechina-course-runner` 后提供课程网址及完成要求。

## 运行条件

需要 macOS、Google Chrome、Python 3 和 AppleScript（`osascript`）；运行环境须允许控制 Chrome。脚本只依赖 Python 标准库。离线测试另需 Node.js。所有脚本路径均相对于本 skill 目录，执行前定位安装后的实际路径。

持续运行优先使用宿主提供的当前线程 heartbeat；Claude Code 或其他宿主没有同等唤醒能力时，不声称可以持续后台运行，应完成当前可执行状态后说明需要用户再次唤醒。

用户只需提供课程网址并要求完成课程，不必提供课程 ID、小节数量或每节指令。使用 skill 目录下的辅助脚本：

```bash
python3 scripts/cmechina_chrome.py --url 'https://www.cmechina.net/cme/study2.jsp?course_id=202601015547&courseware_id=02' status
```

开始课程或提交考试前必须获得用户授权；当前对话中已有的授权可以沿用。Chrome 必须开启 **查看 → 开发者 → 允许 Apple 事件中的 JavaScript**。

“完成该网页所有小节的视频及考试”已经授权该课程内的播放、普通流程签到、答题提交和小节跳转，无需每节重复确认。网址只是输入，真正执行以浏览器当前状态为准。脚本支持 `--url` 或 `--course-id`，操作已有匹配标签页；`TAB_NOT_FOUND` 时使用浏览器工具打开用户原始网址，不创建重复标签。若存在多个同课程标签，只保留一个操作目标，避免多个执行者同时提交。

## 持续执行与完成条件

首次运行必须读取 [references/workflow.md](references/workflow.md)。按以下状态流程连续处理，直到视频正在健康播放、确实需要用户操作或全部完成；不要执行一个点击后就结束当前轮。

该任务需要跨越长视频：使用产品的当前线程 heartbeat，恢复检查间隔为 **10 分钟**。先查找相同课程的已有任务，复用或更新，不重复创建；提示词固定课程网址和本 skill 路径，不写死“当前第几节”。每轮根据真实页面重新判断；健康播放保持安静。考试和结果页在同一轮处理，直到下一段视频开始播放。若产品无法持续唤醒，明确说明不能保证后台连续执行，不把挂载页面监听器说成完整后台任务。

`status.progress` 在课程列表提供总数、已通过数及每节状态；只有 `total > 0` 且 `allPassed: true` 才可报告全部完成，并删除该课程的监测任务。最后一节通过页只是候选结果，仍须返回课程列表验证。申请学分、支付和其他课程不在自动执行范围。

## 状态驱动流程

1. 用 `status` 检查匹配课程的标签页，不要假定它是当前活动标签页。
2. 每次状态检查后先查看 `popup` 字段；出现普通站内弹窗时运行 `dismiss`。进入视频页后运行 `arm --resume`：它会先消除已有的普通弹窗、挂载后续弹窗观察器，再保持 1 倍速播放并给当前 `<video>` 元素挂载 `ended` 监听器。监听器会先短暂等待网站自身的完成处理，再点击文字严格等于 `本节考试` 的可见链接；入口尚未渲染时会有限重试，避免一次查找失败后遗失考试入口。
3. 监听器只在当前页面有效。页面跳转、刷新、视频元素被替换或进入新小节后，都要重新挂载。周期监测可以检查并补挂监听器，但不得用经过时间判断视频是否完成。
4. 发现 `exam.jsp` 时，优先立刻运行 `exam`，不要等待下一次视频状态检查。根据课程内容和权威来源判断答案。用 `select --answers A,B,...` 选择答案并检查返回结果；只有考试提交已获授权时才能运行 `submit`。
5. 用 `status` 读取结果页。如果网站指出错误题目，保留已确认的正确答案，只修改错误题，再运行 `retry` 返回试卷；没有可靠依据时停止并询问用户。
6. 考试通过后运行 `advance`，重新读取状态。`course-pass` 页的 `advance` 会返回课程列表验证；列表中的 `advance` 打开第一节未通过的小节，支持第十节及以后。进入视频页立即运行 `arm --resume`。
7. 只有课程列表明确显示所有必修小节均已通过，任务才算完成。

导航后页面尚未就绪时，短暂等待并重新读取状态，最多三次；不得把暂时的 `NO_VIDEO` 当作结束，也不得盲目连续 `advance`。选择答案或提交前再次确认仍在同一节的考试页；若已被其他执行者推进，则丢弃旧答案并重新判断，禁止对下一节使用上一节答案。

## 弹窗处理

对页面内可见的对话框、遮罩层和提示框运行 `dismiss`，点击其中语义明确的消除按钮，例如“关闭”“签到”“取消”“稍后”“知道了”“确定”或“继续播放”。视频页的 `arm` 会安装页面内观察器，自动处理之后动态出现的同类弹窗；页面跳转或刷新后必须重新运行。若弹窗没有可识别的安全按钮，保留弹窗并根据 `popup.unhandled` 判断，不得点击含义不明的控件。

## 签到处理

`status` 会把可见的“签到”入口报告为 `signin: true`。这里的签到按钮是网站流程标记：`dismiss` 和视频页观察器应直接点击文字严格等于“签到”的可见按钮，然后继续检查页面状态；按钮不在弹窗容器内时也要处理。若同一弹窗还包含人脸、实名、验证码、“本人操作”或“学员本人”等身份验证特征，则按受保护弹窗停止，不自动确认。

遇到登录失效、身份或人脸验证、明确要求学员亲自操作的声明、播放行为异常、题目缺失或答案无法可靠判断时，停止相关操作并通知用户。不得直接调用完成状态、学习时长、签到、成绩或进度接口；不得合成观看时长、绕过播放器检测或修改后端状态。

需要了解页面状态、结束事件、考试结果处理或周期监测时，读取 [references/workflow.md](references/workflow.md)。
